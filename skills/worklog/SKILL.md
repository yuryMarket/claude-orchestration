# Worklog закрытия задачи

Составляешь worklog о том, как была решена задача, и публикуешь его комментарием в Jira от имени пользователя.

**Источник истины по формату и содержанию — `~/.claude/rules/ticket-worklog.md`. Прочитай его перед написанием текста и следуй ему дословно.** Ниже — только алгоритм.

Ключевые инварианты (полный свод — в правиле):
- Ровно одна секция: `## Work log — how this request was handled`
- Bullet-список без нумерации; каждый пункт заканчивается `Resources and result:` + проверенные ссылки
- Первое лицо, голос инженера; без упоминания ИИ, агентов, сессий и инструментов
- Язык тикета; для THD Jira — английский
- Никаких секций `Request` / `Answer` / `Result` / `Follow-ups`

## Входные данные

- `$ARGUMENTS` — ticket ID
- Если не передан — резолюция активного тикета:
  1. Primary: session_id из строки контекста `AIDD session_id: <S>` → файл `~/.claude/sessions/aidd/<S>.json`, поле `ticket`
  2. Fallback (legacy): содержимое `docs/.active_ticket`
  3. Если пусто — спроси пользователя, по какому тикету составлять worklog

## Алгоритм

1. Определи тикет (см. «Входные данные»).

2. Прочитай `~/.claude/rules/ticket-worklog.md`.

3. Собери факты — ничего не выдумывать, каждый пункт worklog подтверждён источником:
   - **Тикет**: `Agent(quick-lookup)` с промптом
     `Получи Jira тикет <ID>. Верни: title, status, description дословно, все комментарии с авторами и датами, remote links/PR, историю изменений статусов.`
   - **Транскрипты сессий**: `grep -l` по `~/.claude/projects/<slug текущего cwd>/*.jsonl` (slug = абсолютный путь cwd с заменой `/` на `-`) по ID тикета, именам ресурсов/файлов из описания, имени автора запроса. Найденные файлы прогнать скриптом-дампом: Write скрипта в scratchpad → `python3 <абсолютный путь>` (извлечь user-промпты, текст ассистента, tool-вызовы с timestamp) → прочитать релевантный фрагмент.
   - **Локальные артефакты**: `docs/prd|research|plan|tasklist|reports|investigations/<ticket>*`, `~/docs/quick-lookup/`, `~/infra-operator-logs/`
   - **GitHub**: `gh pr view <N> --json url,state,mergedAt,title`; `gh api repos/<org>/<repo>/contents/<path> --jq .html_url` — каждая ссылка в worklog должна быть проверена и вести на `blob/main/...`
   - **Текущее состояние** (при необходимости): read-only проверки `bq` / `gcloud` / `kubectl` для подтверждения фактов

4. Напиши файл:
   - В проекте: `docs/reports/<ticket>-worklog.md`
   - Вне проекта: `~/docs/reports/<ticket>-worklog.md` (режимы — `~/.claude/rules/docs-storage.md`)
   - Структура, голос и формат — строго по `~/.claude/rules/ticket-worklog.md`
   - Если файл уже существует — обнови его, не создавай версий и копий

5. **СТОП — черновик на подтверждение.** Покажи пользователю содержимое файла (или путь + сводку ≤10 строк: число шагов, число ссылок, отмеченные тупики) и жди подтверждения или правок. Итерации правок вносятся в тот же файл. Без явного «ок» дальше не идти.

6. Публикация (только после подтверждения) — `Agent(general-purpose)` с промптом:
   ```
   Добавь комментарий в Jira-тикет <ID> через mcp__atlassian__jira_add_comment.
   Тело — полное содержимое файла <абсолютный путь>, дословно, Markdown как есть
   (тул конвертирует в ADF, не переводить в wiki-разметку).
   Статус и поля тикета не менять.
   После — прочитай комментарий обратно через jira_get_issue и проверь:
   bullet-список отрендерился, у каждого пункта есть "Resources and result:" со ссылками,
   URL не разорваны.
   Верни id/URL комментария и результат проверки, ≤8 строк.
   ```
   Если комментарий уже публиковался (id известен из предыдущей итерации или найден среди комментариев тикета по заголовку `Work log`) — использовать `mcp__atlassian__jira_edit_comment` того же комментария, новый не создавать.

7. Итог пользователю:
   - URL комментария: `https://thd.atlassian.net/browse/<ID>?focusedCommentId=<id>`
   - Путь к файлу worklog
   - Замечания проверки рендера (например, разорванная ссылка)
   - Явно: статус тикета не менялся

## Запреты

- Не менять статус, поля, assignee тикета — только комментарий
- Не публиковать в Jira без подтверждения пользователя
- Не вызывать `mcp__*` напрямую из скилла — только через `Agent` (см. `~/.claude/rules/mcp-isolation.md`)
- Не использовать нумерованные списки и URL со спецсимволами `!`
- Не упоминать ИИ, агентов, субагентов, сессии и инструменты в тексте worklog
- Не выдумывать шаги, ссылки и результаты — только подтверждённые факты
- Не создавать второй комментарий `Work log` в том же тикете
